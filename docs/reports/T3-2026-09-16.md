# T3. Разведка: перенос окна на другой рабочий стол

- **Статус:** DONE, с одной непроверенной частью (см. «Осталось»)
- **Ветка:** `feat/T3-space-move-spike` (база `wave/scratchpad-w1`, 96c652d)
- **Подробный отчёт:** [`docs/plans/research/scratchpad-space-move.md`](../plans/research/scratchpad-space-move.md)

## Что сделано и зачем

Нашёл способ переносить окна чужих приложений между рабочими столами на macOS 27 без scripting addition. Это `SLSBridgedMoveWindowsToManagedSpaceOperation` + `-performWithWMBridgeDelegate`: публичные ObjC-классы SkyLight из macOS 26+, на которые с мая 2026 перешёл yabai (#2788). Способ оформлен как `sys::space_move::move_window_to_space`, плюс добавлены команды devtool.

## Изменённые файлы

- `src/sys.rs` — `pub mod space_move;`
- `src/sys/space_move.rs` — `move_window_to_space`, `spaces_for_window`, `space_id_from_raw`, тест преобразования `SpaceId`
- `examples/devtool.rs` — `devtool space window <wid>`, `devtool space move-window <wid> <space>`
- `docs/plans/research/scratchpad-space-move.md` — отчёт разведки

## Ключевые решения

- Выбран `performWithWMBridgeDelegate`, а не локальный символ `SLSPerformAsynchronousBridgedWindowManagementOperation`, который yabai ищет разбором symtab. По дизассемблеру оба пути делают одно и то же, но публичный метод не требует разбора Mach-O.
- `SLSMoveWindowsToManagedSpace` и обход через compat id вживую не работают (`SLSSetWindowListWorkspace` → 1006). В коде их нет.
- Для `SpaceId` ↔ `u64` используется `transmute` (тип `repr(transparent)`), потому что публичного конструктора у `SpaceId` нет, а `screen.rs` в этой задаче только для чтения.

## Как проверено

- Живая проверка на своём окне TextEdit (wid 44103): перенос 4→5→6→7→8→266→4. Окно переезжало за ~60–100 мс, в том числе при вызове из фонового потока. Текущий стол пользователя (430) не менялся. TextEdit в конце закрыт без сохранения.
- `cargo build --examples` — без ошибок и предупреждений.
- `cargo test` — 233 + 7 тестов, все зелёные. Новый тест `sys::space_move::tests::space_id_round_trips` проходит.
- `rustfmt` (nightly, edition 2024) прогнан по изменённым файлам.

## Осталось / риски

- Перенос на **видимый** текущий обычный стол не проверен: текущий стол пользователя — полноэкранный видеоплеер, переключать его я не стал. Способ «свернуть/развернуть» не проверен по той же причине.
- Работа с полностью включённым SIP не проверена на этой машине. Что способ работает и так, известно только из yabai (#2788).
- API асинхронный и ошибок не возвращает: при несуществующем столе вызов молча ничего не делает.

## Обнаружено

- Текущий стол на машине может быть полноэкранным (type 4). T6 должен решить, что делать в этом случае.
- `cargo fmt` через `PATH=…nightly…` в этом окружении подхватывает stable rustfmt и переформатирует всё дерево. Надёжнее вызывать `~/.rustup/toolchains/nightly-aarch64-apple-darwin/bin/rustfmt --edition 2024 <файлы>`.
- `performSynchronousBridgedWindowManagementOperation:` роняет процесс (SIGTRAP).
