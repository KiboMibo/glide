# T4. Поток приложения: скрытие

**Ветка:** `feat/T4-app-hidden` → `wave/scratchpad-w2` · **План:** `docs/plans/2026-09-16-scratchpad.md`
**Коммиты:** `e88b5b1` (стенд), `0230bd5` (функция), коммит с этим отчётом

## Что сделано

Реализован контракт 5.5. Поток приложения выполняет `Request::SetHidden(bool)` через `sys::app::set_app_hidden`. Если вызов не удался, пишется `warn!`. Поток подписан на `AXApplicationHidden` и `AXApplicationShown` и по ним отправляет `Event::ApplicationHiddenChanged(pid, bool)`. Reactor хранит флаг в `AppState` и отдаёт его методом `pub fn is_app_hidden(&self, pid) -> bool`. Для неизвестного pid метод возвращает `false`. Тестовый стенд теперь обрабатывает `SetHidden` и не падает на нём.

**Как Reactor узнаёт начальное состояние:** в `AppInfo` (`src/sys/app.rs`) добавлено поле `is_hidden: bool` с `#[serde(default)]`. Это единственное разрешённое исключение по файлам. `From<&NSRunningApplication>` заполняет поле из `isHidden()`. `State::init` перечитывает значение через `sys::app::is_app_hidden(pid)`: это происходит уже после подписки на уведомления и прямо перед отправкой `ApplicationLaunched`, поэтому промежуточное изменение не теряется. Reactor при `ApplicationLaunched` копирует `info.is_hidden` в `AppState`. Второй вариант, при котором Reactor сам спрашивает `is_app_hidden` при запуске, отвергнут: это был бы системный вызов в Reactor, и воспроизведение trace перестало бы быть детерминированным.

## Решения

- **Константы уведомлений** уже есть в `accessibility-sys` (ревизия `1e827c4`): `kAXApplicationHiddenNotification` и `kAXApplicationShownNotification`. Свои строковые константы не понадобились.
- **Подписка на hide/show не блокирует управление приложением.** Обязательные уведомления (`APP_NOTIFICATIONS`) при ошибке повторяются с backoff, и если подписаться так и не удалось, приложение не берётся под управление. Hide/show регистрируются один раз после обязательных, ошибка пишется в `debug!`. Иначе приложение, которое отказывается от этих уведомлений, ждало бы таймаут и выпадало из управления.
- **Состояние берётся из типа уведомления** (`Hidden` → `true`, `Shown` → `false`), а не перечитывается у `NSRunningApplication`. Свойства `NSRunningApplication` обновляются на главном run loop, а поток приложения работает не на нём, поэтому перечитанное значение могло бы оказаться устаревшим.
- **Стенд: у каждого приложения свой канал.** В `Request::SetHidden(bool)` нет pid (так задано контрактом), а для ответа `ApplicationHiddenChanged(pid, _)` он нужен. Стенд даёт каждому приложению отдельный канал, и `tagged_requests()` возвращает пары `(pid, Request)`. Из-за этого запросы разных приложений в `requests()` теперь сгруппированы по pid, а не идут в порядке отправки. Все прежние тесты проходят. Старый `simulate_events_for_requests(Vec<Request>)` оставлен, чтобы не трогать существующие тесты. Если ему передать `SetHidden`, он паникует и в сообщении предлагает использовать `tagged_requests`. Рефакторинг стенда вынесен в отдельный коммит.
- **Стенд отвечает на каждый `SetHidden`**, даже если состояние не меняется, и записывает последнее запрошенное значение в `Apps::hidden`. Настоящая macOS при повторном hide уведомления не шлёт. Для Reactor это неважно: обработка идемпотентна.
- `ApplicationHiddenChanged` для неизвестного pid игнорируется, запись в `apps` не создаётся.

## За рамками

- `ToggleScratchpad` и LayoutManager не менялись, это задача T5. Reactor пока нигде не отправляет `SetHidden`.
- На живой системе не проверено, что уведомления hide/show действительно приходят (например, по Cmd+H) и что `set_app_hidden` скрывает приложение. По условиям задачи WM не запускался, реальные приложения в тестах не скрывались.
- Если приложение не принимает подписку на hide/show, Reactor не узнает о ручном Cmd+H. В лог при этом попадает только `debug!`.

## Ревьюеру

- `src/actor/reactor/main_window.rs` изменён вне списка файлов задачи: добавлена одна строка в список игнорируемых событий.
- В `src/actor/reactor/testing.rs` поменялся порядок запросов между приложениями: теперь они сгруппированы по pid. Для T5 и R2-test: чтобы стенд ответил на `SetHidden`, используйте `simulate_until_quiet`, `simulate_events` или `tagged_requests`.
