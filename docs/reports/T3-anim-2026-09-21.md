# T3. Подключение исправления origin — отчёт

- **Дата:** 2026-09-21
- **Ветка:** `feat/T3-anim-origin` (от `wave/scroll-animation-w1`)
- **Статус:** DONE

## Что сделано

1. `src/actor/layout.rs`: `vp.set_screen_width(screen.size.width)` заменён на `vp.set_screen(...)` в обоих местах, где он вызывался:
   - `update_viewport_for_focus` — `vp.set_screen(screen)`;
   - `handle_scroll_wheel` — `vp.set_screen(*screen)`.
   Других вызовов не было.
2. `src/model/scroll_viewport.rs`: удалён ставший неиспользуемым `set_screen_width`. Тесты модели его не вызывали.
3. `ARCHITECTURE.md`, «Scroll layout» → «Viewport and animation»: offset отсчитывается от левого края экрана (`set_screen`); кадры скролла идут в `AnimationManager` сообщениями `ScrollFrame` (`BeginWindowAnimation` один раз, position-only `AnimationFrame`) и `ScrollEnd` (финальные кадры и `EndWindowAnimation`).

## Тест

`actor::layout::tests::scroll_layout_columns_stay_on_a_screen_with_nonzero_origin` — на уровне `LayoutManager`, экраны 900×600 с `origin.x = 1920` и `−1920`, три окна в скролл-раскладке, `animate = false`. Фокус по очереди на окна 1, 3, 1; после каждого — `update_viewport_for_focus` и `handle_scroll_wheel` (с нулевой дельтой, только для `set_screen`), затем `calculate_layout`. Проверяется:
- рамка окна в фокусе целиком внутри экрана;
- каждое окно либо на экране, либо припарковано вплотную к его краю (не на соседнем мониторе).

Без исправления тест падает для обоих origin: при 1920 окно 1 рисуется на x=450 (основной монитор), при −1920 — на x=0.
