# T1. Пиксельная прокрутка, инерция, модификатор

**Ветка:** `feat/T1-scroll-trackpad` → `wave/scroll-trackpad-w1` · **План:** `docs/plans/2026-09-21-scroll-trackpad.md`
**Коммиты:** `986f287` feat: настраиваемый модификатор, `b462e24` improve: прокрутка трекпадом по расстоянию

## Что сделано

Свайп двумя пальцами по трекпаду с зажатым модификатором теперь листает скролл-раскладку по пройденному расстоянию: примерно одна ширина колонки — одна колонка. Раньше каждое событие жеста считалось делением колеса, и один свайп пролистывал много колонок. Инерционные события игнорируются, новый жест начинается с нуля. Колесо мыши работает как раньше. Модификатор задаётся настройкой `settings.experimental.scroll.scroll_modifier` (`alt` по умолчанию, также `ctrl`, `cmd`, `shift`).

## Решения

**Формула порога для continuous-событий.** Порог шага остаётся прежним `step_threshold = W / min(колонок, 3)` (W — ширина экрана в pt, «колонок» — число колонок в раскладке). Пиксельная дельта масштабируется так:

```
effective = delta_pt × scroll_sensitivity / 20
одна колонка, когда Σ effective ≥ step_threshold
⇒ нужный путь пальцами = step_threshold × 20 / scroll_sensitivity   (pt)
```

Константа 20 (`CONTINUOUS_SCROLL_REFERENCE_SENSITIVITY` в `layout.rs`) — это чувствительность, при которой путь равен ширине шага. Больше чувствительность — короче путь, при 0 трекпад не листает.

Экран 1920 pt, 2 колонки, `scroll_sensitivity = 20.0`: `step_threshold = 1920 / 2 = 960`, путь = `960 × 20 / 20 = 960 pt` на колонку. При чувствительности 40 — 480 pt. Остаток переносится между событиями одного жеста. Если одно событие само больше двух порогов, будет два шага (как и раньше в ветке непрерывных дельт).

- **Где проверять фазы.** Сброс и игнор инерции живут в `LayoutManager::handle_scroll_wheel` и `ViewportState`. `mouse.rs` только переводит числа полей в `ScrollPhase`: `MayBegin` → `Began`, `Cancelled` → `Ended`, любое ненулевое значение momentum phase (Begin/Continue/End = 1/2/3) → `Momentum`.
- **Совместимость трасс.** Поля события с `#[serde(default)]`; старое событие читается как «не continuous, фаза None, модификаторы пустые», а Reactor считает Alt зажатым по `alt_held`. Строка конфига в старой трассе не содержит `scroll_modifier`, поэтому у поля стоит `#[serde(default)]`, а у `ScrollModifier` — `#[default] Alt`. Это единственный ручной Default: он нужен только для отсутствующего поля в записанных трассах, значение для пользователей берётся из `glide.default.toml`. Без него старые трассы не загрузились бы уже на строке конфига.
- Константы полей CGEvent сверены с `CGEventTypes.h` из локального SDK (`/Library/Developer/CommandLineTools/SDKs/MacOSX.sdk/System/Library/Frameworks/CoreGraphics.framework/Headers/CGEventTypes.h`): `kCGScrollWheelEventScrollPhase = 99`, `kCGScrollWheelEventMomentumPhase = 123`, `kCGScrollWheelEventIsContinuous = 88`, `kCGScrollWheelEventPointDeltaAxis1/2 = 96/97`; `CGScrollPhase`: Began=1, Changed=2, Ended=4, Cancelled=8, MayBegin=128; `CGMomentumScrollPhase`: None=0, Begin=1, Continue=2, End=3. Документация Apple: https://developer.apple.com/documentation/coregraphics/cgeventfield.

## За рамками

- Живая проверка на трекпаде не делалась (запуск WM запрещён). Значения полей взяты из заголовка SDK, реальное поведение на macOS 27 должен проверить человек: Option + два пальца — одна колонка на свайп примерно в ширину колонки; колесо — одна колонка на деление.
- Вертикальный свайп тоже листает, если горизонтальная дельта события 0. Так было и раньше: Reactor берёт `delta_x`, а если она 0, то `delta_y`.

## Риски и точки внимания

- `step_threshold` зависит от числа колонок в раскладке, а не от `visible_columns`: при 1920 pt и трёх или более колонках порог 640 pt, при двух — 960 pt. Так было и раньше, и так записано в плане («как сейчас step_threshold»). Если нужно, чтобы порог совпадал с видимой шириной колонки, лучше считать `W / visible_columns`.
- Mouse теперь шлёт и события с нулевой дельтой, если у них есть фаза (Began/Ended). Это несколько лишних событий на жест, и они попадают в трассу.
