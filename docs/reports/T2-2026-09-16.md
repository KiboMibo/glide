# T2. sys: управление приложением

**Ветка:** `feat/T2-app-control` → `wave/scratchpad-w1` · **План:** `docs/plans/2026-09-16-scratchpad.md`
**Коммиты:** `5742c18` (код), коммит с этим отчётом

## Что сделано

В `src/sys/app.rs` добавлены четыре функции из контракта 5.4: `set_app_hidden`, `is_app_hidden`, `activate_app` и `launch_app`. Первые три работают через `NSRunningApplication`: процесс ищется существующим хелпером `NSRunningApplicationExt::with_process_id`. `launch_app` проверяет bundle id и запускает `/usr/bin/open -b <id>` в отдельном потоке без shell. Код выхода и stderr пишутся в лог. Пока эти функции никто не вызывает, их подключит T4/T5.

## Изменения

| Файл | Что |
|------|-----|
| `src/sys/app.rs` | 4 функции из контракта 5.4, `enum LaunchError` (`EmptyBundleId`, `InvalidBundleId(String)`, на `thiserror`), приватная `validate_bundle_id` и модуль тестов |

`Cargo.toml` не менялся: нужные features (`NSRunningApplication`) уже подключены.

## Решения

- **Сигнатуры** совпадают с 5.4. Контракт не описывал тип `LaunchError`, поэтому его пришлось определить здесь: `pub enum LaunchError` с `Debug + PartialEq + Eq + Display + Error`.
- **Проверка bundle id строже контракта.** Кроме условия «непустой, только `[A-Za-z0-9.-]`» id не может начинаться с `-`. Иначе `-a` или `-n` прошёл бы проверку и `open` мог бы прочитать его как свой флаг. Настоящие bundle id (формат UTI) с дефиса не начинаются, поэтому корректных значений это ограничение не отсекает.
- **`activate_app`** передаёт пустые `NSApplicationActivationOptions`. Флаг `ActivateAllWindows` не нужен по контракту. Флаг `ActivateIgnoringOtherApps` в objc2 помечен `#[deprecated]`, и с macOS 14 он ничего не делает.
- **`#[allow(dead_code)]` не понадобился**: `sys` объявлен как `pub mod` в библиотеке, поэтому неиспользуемые `pub fn` не дают предупреждений.
- **Нет `unwrap`** на результатах Objective-C вызовов: nil превращается в `None` через `Option<Retained<_>>`, а BOOL передаётся наружу как есть.

## За рамками

- Скрытие, показ и активация настоящих приложений в тестах не проверялись: по условиям задачи тесты не трогают приложения пользователя. Поведение на живой системе проверят T4/T5 и сам пользователь.
- `activate_app` может вернуть `true`, но приложение не активируется: так устроена кооперативная активация в macOS 14+, если Glide не активен. Поэтому фокус нужно ставить через `focus_window` → `make_key_window`, как уже делает RaiseManager. Это стоит учесть в T5.

## Ревьюеру

- Проверка bundle id строже контракта (ведущий `-`). Если это нежелательно, достаточно убрать одно условие.

## Обнаружено

- `PATH=~/.rustup/toolchains/nightly-aarch64-apple-darwin/bin:$PATH cargo fmt` в этом окружении не работает. `cargo` и `rustfmt` берутся из `/opt/homebrew/bin` (stable, без rustup-прокси), поэтому получаются предупреждения «unstable features» и переформатируется весь репозиторий. Кроме того, `cargo +nightly` недоступен. Работает прямой вызов `~/.rustup/toolchains/nightly-aarch64-apple-darwin/bin/rustfmt --edition 2024 <файлы>`.
- Worktree агента создаётся от старого коммита (`3a92f97`), а не от `wave/scratchpad-w1`. Ветку нужно создавать явно от базы волны.
