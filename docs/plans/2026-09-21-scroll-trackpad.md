# План: плавная прокрутка скролл-раскладки с трекпада

- **Дата:** 2026-09-21
- **Статус:** в работе (F2 по итогам живой проверки)
- **Цель:** листать колонки скролл-раскладки свайпом по трекпаду предсказуемо (один свайп примерно на ширину колонки — одна колонка), без рывков от инерции, с настраиваемым модификатором.

## 1. Контекст

Glide — тайлинговый оконный менеджер для macOS на Rust. Прочитай `CLAUDE.md`, `ARCHITECTURE.md` (раздел «Scroll layout») и `agents.local.md`. Запрещено запускать `cargo run`, `glide launch`, сам WM. Форматирование — только `~/.rustup/toolchains/nightly-aarch64-apple-darwin/bin/rustfmt --edition 2024 <изменённые .rs>` (не `cargo fmt`).

Как сейчас:
- `src/actor/mouse.rs` ~186-198: событие `CGEventType::ScrollWheel` читает **целочисленные построчные** дельты `SCROLL_WHEEL_EVENT_DELTA_AXIS_1/2` и флаг Option, шлёт `reactor::Event::ScrollWheel { delta_x, delta_y, alt_held }` (`src/actor/reactor.rs` ~217).
- `src/actor/reactor.rs` ~922-943: если `scroll.enable` и Option зажат — `layout.handle_scroll_wheel(space, delta, screen, config)`; `delta` = `delta_x`, если не 0, иначе `delta_y`. `// TODO: Make the modifier key configurable.`
- `src/actor/layout.rs` ~1442-1518 `handle_scroll_wheel`: `is_discrete = |delta| < 10 && delta.fract() == 0` — дискретное событие двигает на целый шаг; накопление через `ViewportState::accumulate_scroll` (`src/model/scroll_viewport.rs` ~130), затем выделение сдвигается на `steps` колонок с анимацией.
- Проблема: у трекпада целочисленная построчная дельта маленькая и целая, поэтому каждое событие жеста считается «дискретным» и даёт целый шаг — один свайп пролистывает много колонок. Инерционные (momentum) события после отрыва пальцев добавляют ещё шагов.
- Событие `ScrollWheel` пишется в трассу (record/replay) — новые поля должны быть `#[serde(default)]`, старые трассы должны читаться.

Доступные поля CGEvent (crate `core-graphics` 0.25): `SCROLL_WHEEL_EVENT_IS_CONTINUOUS` (88), `SCROLL_WHEEL_EVENT_POINT_DELTA_AXIS_1/2` (96/97), `SCROLL_WHEEL_EVENT_FIXED_POINT_DELTA_AXIS_1/2` (93/94). Фазы жеста — поля 99 (scroll phase: began=1, changed=2, ended=4, cancelled=8, may_begin=128) и 123 (momentum phase: 0 = нет инерции, иначе инерция); если в crate нет констант — объявить числа в `mouse.rs` с комментарием.

## 2. Цель и критерии готовности

1. С трекпада (continuous-события) колонки листаются по пиксельным дельтам: жест примерно на ширину колонки × чувствительность = одна колонка; мелкие движения не листают.
2. Инерционные события (momentum phase ≠ 0) игнорируются; начало нового жеста (phase began/may_begin) сбрасывает накопленный прогресс.
3. Колесо мыши (не continuous) работает как раньше: одно деление — одна колонка.
4. Модификатор задаётся `settings.experimental.scroll.scroll_modifier` = `"alt"` (по умолчанию, как сейчас) | `"ctrl"` | `"cmd"` | `"shift"`; неизвестное значение — ошибка конфига. Достаточно, чтобы выбранный модификатор был зажат; другие зажатые модификаторы не мешают (как сейчас с Option).
5. Старые трассы воспроизводятся. `cargo test` зелёный, новые ветви покрыты тестами, `glide.default.toml` документирует новую настройку и что жест — модификатор + два пальца.

## 3. Скоуп

**Входит:** пиксельные дельты для continuous-событий, игнор инерции, сброс прогресса в начале жеста, настраиваемый модификатор, документация.
**Не входит:** жест 3/4 пальцами (MultitouchSupport), лента, непрерывно следующая за пальцами (панорамирование viewport с доводкой), жест без модификатора, вертикальная прокрутка как отдельная ось.

## 4. Архитектурные решения

- `mouse.rs` только читает поля события и передаёт факты (continuous, дельты в точках, фаза, инерция, какие модификаторы зажаты); решение «листать или нет» и накопление — в LayoutManager/модели, как сейчас.
- Порог для continuous-событий — ширина колонки (как сейчас `step_threshold`) делённая на `scroll_sensitivity`-масштаб (сохранить смысл: больше чувствительность — меньше нужно вести пальцем). Точную формулу выбирает исполнитель и описывает в отчёте с числом для 1920px и значений по умолчанию.
- Проверка модификатора — в Reactor (как сейчас), по флагам из события.

## 5. Контракты

```rust
// src/actor/reactor.rs
ScrollWheel {
    delta_x: f64,
    delta_y: f64,
    alt_held: bool,               // оставить для совместимости трасс
    #[serde(default)] modifiers: ScrollModifiers,   // какие модификаторы зажаты
    #[serde(default)] continuous: bool,
    #[serde(default)] phase: ScrollPhase,           // None | Began | Changed | Ended | Momentum
}

// src/config.rs, ScrollConfig
pub scroll_modifier: ScrollModifier, // snake_case: alt | ctrl | cmd | shift; default из glide.default.toml = "alt"
```
Для continuous-событий `delta_x/delta_y` — пиксельные (point) дельты; для колеса — как сейчас. Типы `ScrollModifiers`/`ScrollPhase` исполнитель определяет сам (Serialize/Deserialize, Default), старые трассы без полей читаются как «alt по `alt_held`, не continuous, фаза None».

### [x] F2. Исправления по живой проверке

- **Основание:** трасса пользователя (2026-09-21, macOS 27, трекпад MacBook). Путь пальцев за горизонтальные свайпы почти на всю ширину трекпада: 85 и 249 pt (инерция 515 и 1518 pt — игнорируется); порог 250 pt не достигнут ни разу. 4 из 6 жестов были вертикальными (|dy| 177–337 pt при |dx| 4–22 pt); код брал `delta_x`, если он ≠ 0, поэтому вертикальные жесты терялись. Пример события: `ScrollWheel(delta_x:6.0,delta_y:1.0,...,continuous:true,phase:Changed)`; `MayBegin` и `Began` приходят подряд (оба → `Began`).
- **Решения пользователя:** (1) один свайп = одна колонка; (2) вертикальный свайп тоже листает, ось — доминирующая.
- **Файлы (владеет):** `src/actor/layout.rs`, `src/actor/reactor.rs`, `src/model/scroll_viewport.rs`, `glide.default.toml`, `docs/reports/F2-scroll-2026-09-21.md`.

**Что сделать**
1. Трекпад (continuous, есть фазы): в пределах жеста (от `Began` до `Ended`) копить путь пальцев по обеим осям (инерцию игнорировать). Ось — доминирующая по накопленному пути (|Σdx| против |Σdy|), а не по отдельному событию. Как только путь по доминирующей оси достиг порога `TRACKPAD_SWIPE_PT = 40 pt × 20 / scroll_sensitivity`, пролистать ровно одну колонку в сторону жеста; до следующего `Began` больше не листать. `Began` сбрасывает и путь, и признак «уже пролистали».
2. Направление вертикали: вверх — к предыдущей колонке, вниз — к следующей (с учётом `invert_scroll_direction` так же, как для горизонтали). Горизонталь — как сейчас. Сверь знаки с тем, как macOS отдаёт point-дельты при естественной прокрутке, и опиши в отчёте.
3. Continuous без фаз (мыши с плавной прокруткой): нет границ жеста — пропорционально, колонка на каждые `TRACKPAD_SWIPE_PT` по доминирующей оси события.
4. Колесо (дискретное): ось — доминирующая по событию (`|dx|` против `|dy|`), в остальном как раньше.
5. Состояние «жеста» хранить в модели/LayoutManager (детерминированно, из записанных событий). Модель чистая.
6. Обновить описание в `glide.default.toml` (свайп = одна колонка, вертикаль, ~40 pt, `scroll_sensitivity`).

**Критерии приёмки** (тесты; числа — из трассы пользователя)
- Горизонтальный жест Σdx=85 (13 событий Changed) → ровно 1 колонка; Σdx=−249 → ровно 1 колонка в обратную сторону; инерция после них — 0 колонок.
- Вертикальный жест Σ(dx,dy)=(4,−177) → 1 колонка; (−11,238) → 1 колонка в другую сторону.
- Жест короче 40 pt → 0 колонок; `scroll_sensitivity = 40` → порог 20 pt; 0 → не листает.
- `MayBegin`+`Began` подряд не ломают жест.
- Continuous без фаз: 100 pt → 2 колонки.
- Колесо: деление по вертикали и по горизонтали — 1 колонка; `invert_scroll_direction` для всех случаев.
- Старые трассы воспроизводятся; тесты, закреплявшие 250 pt/пропорциональность трекпада, обновлены с объяснением в отчёте.
