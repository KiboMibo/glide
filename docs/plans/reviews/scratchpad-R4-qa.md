## Резюме

Критерии раздела 2 выполнены на уровне кода и тестов. Правило `scratchpad` делает окно плавающим. Toggle запускает, показывает (с переносом на текущий стол) и прячет окно. `cargo test` зелёный, сборка всех целей без предупреждений. Критерий 4 («⌘⌥K показывает и прячет Keyguard на машине пользователя») можно закрыть только живой проверкой. Её список собран ниже. Блокирующих находок нет. Главное, что осталось:
- история коммитов, которая исказит release notes (решение человека до мержа в `main`);
- закомментированные примеры в `glide.default.toml` не проверяются тестами;
- два узких случая вокруг ожидания переноса. Их стоит посмотреть при живой проверке.

Документация дописана: ограничения scratchpad в `glide.default.toml` и раздел в `README.md`.

### Важные

1. **История коммитов исказит release notes (R3-arch И3 не закрыт, стало хуже)** — `release-please-config.json:25`, `git log develop..wave/scratchpad-w4` и более ранние коммиты волн.
   Что не так:
   - у одной фичи три пользовательские записи `feat:`: `c5fe436`, `b62bc5c`, `26dccf0`;
   - три коммита `fix:` исправляют код, который ещё не выпущен: `eb8f549`, `45e270a`, `cce1afd`;
   - около 40 коммитов `docs:` про план, доску статуса и отчёты. Секция `docs` в release-please не скрыта (`"hidden"` не задан), поэтому все они попадут в «Documentation». Кроме того, сами файлы `docs/plans/**` и `docs/reports/**` лежат в дереве.
   Чем грозит: захламлённые и вводящие в заблуждение release notes, а при PR в upstream — служебные файлы в истории.
   Предлагается: до мержа в `main` человек решает, как переписать историю. Например, собрать фичу в один `feat:` с пользовательским описанием, `fix:` для невыпущенного кода перевести в `internal:`, служебные документы оставить в отдельной ветке или сделать им префикс `chore:`. Эта задача ведёт свои коммиты с префиксом `docs:`, как требует бриф, и тоже попадёт в этот счёт.

2. **Пользовательская секция `[keys]` без `default_keys = true` убирает все стандартные клавиши** — `src/config.rs:423-431` (`ConfigPartial::merge`), `glide.default.toml:49`.
   Что не так: это не ошибка scratchpad, а давнее поведение. Но фича сама подталкивает добавить в конфиг одну клавишу: если конфиг содержит только `"Meta + Alt + K" = …`, пропадут ⌥Z, ⌥⇧E и остальные клавиши. Временный тест это подтвердил. Подготовка живой проверки в R3-qa этого не учитывала.
   Чем грозит: после правки конфига пользователь не может включить стол и выйти из Glide горячей клавишей.
   Сделано: пример в `README.md` содержит `[settings] default_keys = true`. Подготовка живой проверки ниже это тоже учитывает. Код не менялся.

3. **Закомментированные примеры scratchpad в `glide.default.toml` не проверяются тестами** — `src/config.rs:547` (`default_config_is_valid`).
   Что не так: `default_config_is_valid` разбирает только незакомментированную часть файла. Похожая строка в `src/config.rs:1018` использует фиктивный `com.x`, а не текст из файла. Сейчас пример разбирается (проверено временным тестом), но опечатку в будущем никто не заметит.
   Чем грозит: пример в документации разойдётся с синтаксисом. Пользователь скопирует его и получит ошибку конфига.
   Предлагается (R4-test/F4): тест, который берёт из `include_str!("../glide.default.toml")` строку `# "Meta + Alt + K" = …` и блок `#   [[window_rules]]` с `scratchpad`, снимает префикс комментария и прогоняет результат через `Config::parse`. Логика такого теста уже есть в описании выше.

### Замечания

4. **Ожидание переноса не учитывает скрытие приложения** — `src/actor/reactor.rs:574-580`, `:590-594`.
   Если после показа с переносом пользователь в течение 1 с нажмёт ⌘H, `ApplicationHiddenChanged(true)` не снимет запись в `pending_space_moves`. По таймауту `ScratchpadMoveEnded` выставит рамку и отправит фокус окну скрытого приложения. Фокус через `make_key_window`, скорее всего, снова раскроет приложение. Окно для гонки — 1 с, так что вероятность мала. Предлагается: при `ApplicationHiddenChanged(pid, true)` удалять ожидания этого pid. Можно в F4 или отложить. См. живую проверку Л17.

5. **Scratchpad-окно, развёрнутое на весь экран (собственный полноэкранный стол)** — `src/actor/reactor.rs:1408-1424`.
   Такое окно не входит в `visible_windows` текущего стола. Поэтому toggle попытается перенести его на обычный стол через `SLSBridgedMoveWindowsToManagedSpaceOperation`. Что macOS сделает с полноэкранным окном, неизвестно: T3 это не проверял. См. Л16.

6. **Разворачивание окна на другом столе** — `src/actor/app.rs` (`Request::Unminimize`).
   AX может не дотянуться до окна чужого стола (об этом пишет T6). Тестами не покрыть, см. Л10.

7. **Известное и вне скоупа:**
   - конфиг, пришедший через IPC, не проверяет дубли имён и `keys` (R3-arch З5);
   - `Request::Raise` в стенде Reactor всё ещё `todo!()`;
   - scratchpad-окно выбирается как «первое появившееся», если окна появляются по одному (T6, п.8).

## Живая проверка (для человека)

### Сборка и установка (не выполнялось)

```bash
cd ~/Projects/github.com/glide          # рабочая копия с веткой develop после мержа волны 4
git switch develop
cargo build --release                   # target/release/glide_server и target/release/glide
cargo test                              # должно быть 433+ passed
```

Запуск для проверки — прямо из терминала, чтобы вести трассу (`glide launch` не принимает `--record`):

1. Остановить установленный Glide: ⌥⇧E. Если он в автозапуске и поднимется сам, сначала выполнить `glide service uninstall`.
2. Выдать права Accessibility приложению терминала (System Settings → Privacy & Security → Accessibility).
3. Проверить конфиг: `./target/release/glide config verify`.
4. Запустить:
   ```bash
   mkdir -p traces
   RUST_LOG=info,glide_wm::actor::reactor=debug \
     ./target/release/glide_server --record traces/trace-$(date +%Y%m%d-%H%M%S).ron \
     2>&1 | tee traces/log-$(date +%Y%m%d-%H%M%S).txt
   ```
5. Завершить проверку: ⌥⇧E. Вернуть установленную версию: запустить Glide.app или `glide launch`; при необходимости снова `glide service install`.

Постоянная установка сборки как приложения — `cargo packager --release` (так делает `.github/workflows/package.yml`). В `Cargo.toml` прописан `signingIdentity` автора upstream, поэтому для локальной сборки подпись придётся переопределить или убрать. Для проверки это не нужно.

### Подготовка

В `~/.config/glide/glide.toml` добавить (если `[settings]`/`[keys]` уже есть — дописать в них):

```toml
[settings]
default_keys = true     # иначе своя секция [keys] уберёт стандартные клавиши (находка 2)

[keys]
"Meta + Alt + K" = { toggle_scratchpad = { name = "keyguard", launch = "com.artemchep.keyguard" } }

[[window_rules]]
if.app_id = "com.artemchep.keyguard"
scratchpad = "keyguard"
frame = { x = 0.2, y = 0.1, width = 0.6, height = 0.8 }
```

Нужны минимум два рабочих стола (Mission Control). Текущий стол активировать ⌥Z, если стоит `default_disable = true`.

**Что приложить при провале любого пункта:** номер пункта; что ожидалось и что произошло; трассу `traces/trace-*.ron`; лог `traces/log-*.txt` (с `RUST_LOG=info,glide_wm::actor::reactor=debug`); время нажатия, чтобы найти место в логе. Трассу можно воспроизвести: `RUST_LOG=info,glide_wm::actor::reactor=debug cargo run --example devtool -- replay traces/trace-….ron`.

### Сценарии

Источник каждого пункта: Ж — `scratchpad-R3-qa.md`, П — `T6-2026-09-16.md`, Н — новые.

**Основной цикл**

- **Л1. Показ и скрытие (Ж2, критерий 4).** Keyguard открыт на текущем столе. Нажать ⌘⌥K четыре раза с паузой 1 с. Ожидание: окно попеременно скрывается (приложение скрыто, как ⌘H) и появляется в рамке `frame` с фокусом.
- **Л2. Повтор после стороннего обновления окон (Ж1).** ⌘⌥K — Keyguard скрылся. В другом приложении открыть новое окно (⌘N в Safari). ⌘⌥K — Keyguard показался. Через 1–2 с ⌘⌥K. Ожидание: Keyguard скрылся. Если нет, повторить 2–3 раза и приложить трассу.
- **Л3. Ручное скрытие (Ж3).** Фокус на Keyguard, ⌘H. ⌘⌥K: окно в рамке и в фокусе. ⌘⌥K: скрылось.
- **Л4. Окно без фокуса (Ж6).** Keyguard виден, фокус на другом окне. ⌘⌥K: Keyguard получает фокус и рамку и **не** скрывается.
- **Л5. Запуск (Ж4).** Выйти из Keyguard (⌘Q). ⌘⌥K: приложение запускается, окно само встаёт в рамку и получает фокус без второго нажатия.
- **Л6. Закрыто между нажатиями (Ж5).** ⌘⌥K (окно видно), ⌘Q, ⌘⌥K: приложение запускается снова, окно показывается.
- **Л7. Приложение запущено, окно закрыто (Н).** Закрыть окно Keyguard (⌘W), не выходя из приложения (если Keyguard так умеет). ⌘⌥K: ожидается, что `open -b` откроет окно заново и оно будет показано в рамке. Если окно не появилось за 30 с, показ отменяется — записать, что произошло.
- **Л8. Два окна (Ж7).** Если в Keyguard можно открыть второе окно, открыть его. ⌘⌥K при фокусе на втором окне: фокус и рамку получает главное (первое) окно. ⌘⌥K: скрываются оба окна (так задумано).

**Другие рабочие столы**

- **Л9. Окно на другом столе (П1, заменяет Ж9).** Keyguard на столе 2, пользователь на столе 1 (активированном). ⌘⌥K: окно появляется на столе 1 в рамке и с фокусом, **стол не переключается**. Повторное ⌘⌥K скрывает окно. В трассе есть `ScreenSpacesChanged` и нет `ScratchpadMoveEnded` (П8). Если `ScratchpadMoveEnded` есть — WindowServer не увидел окно за 1 с, приложить трассу.
- **Л10. Свёрнутое окно (Ж11, П5).** (а) Свернуть Keyguard (⌘M) на текущем столе, ⌘⌥K: окно разворачивается и показывается. (б) Свернуть на столе 2, перейти на стол 1, ⌘⌥K: записать, развернулось ли окно и где оказалось.
- **Л11. Скрытое приложение на другом столе (П4).** Keyguard на столе 2 скрыт (⌘H). На столе 1 ⌘⌥K: приложение раскрывается, окно приходит на стол 1 с фокусом.
- **Л12. Текущий стол выключен в Glide (П2).** На столе 1 выключить Glide (⌥Z), Keyguard на столе 2. ⌘⌥K: окно приходит на стол 1, раскладка стола 1 не меняется.
- **Л13. Окно на выключенном столе (Ж8).** Стол 2 выключен в Glide, на нём открыть Keyguard. Перейти на активированный стол 1, ⌘⌥K. Ожидание: окно переносится на стол 1 **без повторного запуска** приложения (в логе нет `Launched com.artemchep.keyguard` и `Toggling scratchpad … Launch`). Затем закрыть Keyguard, открыть его на столе 1 вручную: окно не должно неожиданно получить фокус и рамку.
- **Л14. Полноэкранный текущий стол (П3).** Перейти на полноэкранное приложение (зелёная кнопка у Safari). ⌘⌥K: окно **не** переносится, macOS переключается на стол окна, окно в рамке и в фокусе.
- **Л15. Окно, которого Glide не видел (П7).** Выйти из Glide (⌥⇧E), Keyguard оставить открытым на столе 2, перейти на стол 1, запустить Glide и не заходить на стол 2. ⌘⌥K: ожидается известное ограничение — приложение активируется, macOS переключается на стол 2. Записать фактическое поведение.
- **Л16. Scratchpad-окно само в полноэкранном режиме (Н, находка 5).** Развернуть окно Keyguard на весь экран (зелёная кнопка), перейти на обычный стол, ⌘⌥K. Записать, что произошло: переключение на полноэкранный стол, перенос, выход из полноэкранного режима или ничего. Проверить, что после этого ⌘⌥K и ⌘H работают.
- **Л17. ⌘H сразу после показа с переносом (Н, находка 4).** Keyguard на столе 2. На столе 1 ⌘⌥K и **сразу** (быстрее 1 с) ⌘H. Подождать 2 с. Ожидание: приложение остаётся скрытым. Если оно само появилось — приложить трассу (подтверждает находку 4).

**Мониторы**

- **Л18. Два монитора (Ж10, П6).** (а) Keyguard виден и в фокусе на втором мониторе, активен первый (курсор/фокус на первом). ⌘⌥K: окно переезжает на активный экран в рамку. (б) Keyguard на столе второго монитора, который сейчас не показан. Фокус на первом мониторе. ⌘⌥K: окно приходит на текущий стол первого монитора. Записать поведение при фокусе на втором мониторе.

**Прочее**

- **Л19. ToggleFocusFloating (Ж12).** Открыть обычное плавающее окно (⌥⇧Space) и Keyguard. Нажать ⌥Space: Keyguard не должен получать фокус.
- **Л20. Ошибки конфига (Ж13).** В правиле клавиши вписать `launch = "com.x app"`, сохранить, выполнить `glide config update` (или `./target/release/glide config verify`). Ожидание: ошибка с ключом `keys."Meta + Alt + K"` и текстом про допустимые символы. Проверить и дубль: второе правило с `scratchpad = "keyguard"` — ошибка `scratchpad "keyguard" is already used by window_rules[0]`. Вернуть конфиг.
- **Л21. Перезагрузка конфига (Н).** Поменять `frame` (например, `width = 0.4`), `glide config update`. ⌘⌥K ×2: окно показывается в новой рамке.
- **Л22. Старая macOS (П9, если есть машина с macOS < 26).** ⌘⌥K при окне на другом столе: окно показывается без переноса (macOS переключает стол), в трассе `ScratchpadMoveEnded` сразу после команды.
- **Л23. Лог запуска (П10).** В логе от старта до конца проверки нет `ERROR` про `open`/`launch`, нет паник, нет ошибок про `SLSSpaceGetType`/`SLSBridgedMoveWindowsToManagedSpaceOperation`. Отдельно поискать в логе отказы подписки на hide/show (`debug`, R3-arch З6): если Keyguard отказывает, Л3 будет вести себя неверно.
